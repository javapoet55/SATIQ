01 · Guided AI Tutor

Placement: Question Practice. Main column holds the question, answer choices and Check action. The supporting column is a distinct tutor conversation surface with a mint header, progressive help and a composer.

ElementBehavior
Subject tabsSwitch between original Math and Reading & Writing questions. Reset question selection, checked state, hint depth and conversation on switch.
Progressive hintsThree authored levels: identify relevant relationship → point to next operation → narrow the final reasoning. Increment visible hint count, append conversation turn, then disable hints after level three.
Explain this stepExplain the next useful step without revealing the final answer before checking.
Discuss my choiceDisabled until answer selected. Before checking, encourage substitution or relationship testing. After checking, connect the choice to the verified solution.
ComposerAccepts up to 500 characters. Demo explicitly states that custom questions are not interpreted. Production should stream grounded replies with an interrupt control, preserve input on failure, and offer Retry.
CheckDisabled before selection. Reveals correctness, intended answer and explanation. Changing selection removes feedback. Production must retain the first attempt even when students explore other choices.

02 · Mistake Analysis

Placement: Answer Review. A three-stage indicator establishes Reflect → Understand → Try again. The question and prior result remain visible while the student explains their approach.

StageBehavior
ReflectShow selected and correct answers. Require a nonempty explanation before analysis. “Use example reflection” supplies a clearly sample arithmetic error: 60 − 18 = 28, then 28 ÷ 7 = 4. Typed text is escaped before rendering.
UnderstandShow tentative insight and the first incorrect operation. Clearly label that the preview always shows the same scripted analysis. Offer native radio choices: calculation slip, concept gap, question misunderstanding, something else/not sure.
ConfirmStudent confirms or changes the suggested category. The strategy card changes with the selected cause; changing the cause invalidates the previous confirmation.
Try againRoute to the guided tutor on the same algebra question. If entered from a plan review activity, allow completing the review and returning to the plan.

03 · Personalized Daily Plan

Placement: Dashboard. A green summary hero explains the session, a week strip gives date context, task cards form the primary action list, and a supporting panel explains the plan.

ElementBehavior
Time budget10 min: 3 algebra, 2 transitions, 2 review questions; 20 min: 5 algebra, 3 transitions, 2 review questions; 30 min: add an optional 5-question algebra set. Durations total the chosen budget.
Task cardsShow priority, skill, number of questions, time, and a plain-language reason. Start opens a representative question or analysis screen. Demo completion updates the activity count and completion state for the session.
Week stripNovember 2–8, 2026. Earlier days show completed sample routine, Saturday is active, Sunday is an upcoming preview. Actions are disabled for past/future days.
Why this plan?Explain evidence in student language. Scores and streaks remain labeled mock. Production should distinguish observed mastery, insufficient evidence and student goals.

Keep verified solutions and answer keys server-side for assessment modes. Enforce tutor access by session mode on the server. Avoid making outcome claims from answer choice alone: ask for reasoning, present uncertainty, and let the student correct the category. Generated tutor text must be rendered safely. Store minimal student data, isolate accounts and provide deletion controls.

Additional production states

Tutor: ready, generating, streaming, stopped, service unavailable, retry, no hints left, context unavailable. Analysis: empty input, generating, unclear evidence, suggested cause, student override, confirmed, saved/error. Plan: loading, new learner diagnostic, insufficient history, ready, partial completion, complete, regeneration confirmation, offline sync. Preserve drafts and completed activities across changes.

Accessibility and acceptance

Use text with outcome colors, visible focus, real labels, native cause radio groups, aria-pressed on answer choices and date/time options, and a readable DOM order. Conversation updates use a log region. Production should announce completed responses rather than each streamed token, move focus predictably after navigation, and avoid moving focus during typing. Test contrast, keyboard use, screen readers, 200% zoom and 320px width.

Acceptance flow: choose a 10/20/30 minute plan → start algebra → open successive hints → choose/check an answer → complete activity → verify plan count. Separately: enter reflection → explore sample mistake → override cause → confirm → verify tailored strategy → retry. Switch subjects and verify context resets. Test custom text with HTML characters and confirm it remains literal.

Prototype scope: scripted UI states, no AI API, no account/database, no durable plan state. Each planned activity opens one representative question; completing it is a demo action, not completion of the stated full question set. Existing original prototype is preserved.
